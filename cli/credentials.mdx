The `keystroke credentials` command group manages the credential instances stored in the Keystroke credential vault. Credentials are named secrets — API keys, tokens, and other values — that your agents and actions retrieve at runtime without ever touching environment variables or config files directly. You set a credential once from the CLI, and every agent or action with the matching key picks it up automatically.

<Note>
  Credentials are scoped to an organization, user, project, or the global platform. All commands require authentication (`keystroke auth login`) and an active organization. Project-scoped credentials additionally require `--project-id`.
</Note>

## `credentials set` — store a new credential

Creates a new credential instance. The `key` identifies the integration (for example, `exa`, `openai`, or `slack`). The `--set` flag provides the actual secret fields as `field=value` pairs.

```bash
keystroke credentials set <key> --scope <scope> --set <field>=<value>
```

```bash
# Store an API key for the "exa" integration, scoped to the organization
keystroke credentials set exa \
  --scope org \
  --set apiKey=sk-abc123...

# Read the secret value from an environment variable instead of typing it
keystroke credentials set openai \
  --scope org \
  --set apiKey=@env:OPENAI_API_KEY

# Project-scoped credential with a human-readable label
keystroke credentials set stripe \
  --scope project \
  --project-id proj_xyz789 \
  --label "Stripe test key" \
  --set secretKey=sk_test_abc...

# Mark as the default credential for this scope
keystroke credentials set sendgrid \
  --scope org \
  --default \
  --set apiKey=SG.abc123...
```

<ParamField path="<key>" type="string" required>
  The credential key — the integration identifier your agents and actions reference. Use kebab-case (e.g. `exa`, `open-ai`, `my-service`).
</ParamField>

<ParamField path="--scope" type="string" required>
  Visibility scope for the credential. One of:
  - `org` — shared across all projects in the organization
  - `user` — personal to your user account
  - `project` — isolated to a single project (requires `--project-id`)
  - `global` — available to all organizations on the platform
</ParamField>

<ParamField path="--set" type="string" required>
  A credential field in `key=value` format. Pass `key=@env:VAR_NAME` to read the value from an environment variable (the CLI also checks your project's `.env` file as a fallback). Repeat the flag to set multiple fields on a single credential instance.
</ParamField>

<ParamField path="--project-id" type="string">
  Required when `--scope project`. The project ID the credential is bound to.
</ParamField>

<ParamField path="--label" type="string">
  A human-readable label to distinguish this instance from others with the same key in the same scope. Shown in the dashboard and in `credentials list` output.
</ParamField>

<ParamField path="--default" type="flag">
  Mark this instance as the default for its scope. When your code looks up a credential by key without specifying an instance, the default is used.
</ParamField>

## `credentials list` — view stored credentials

Lists all credential instances your user can access in the active organization. The response includes instance IDs, keys, scopes, labels, and metadata — but **never the secret values themselves**.

```bash
keystroke credentials list

# Filter by key
keystroke credentials list --key exa
```

```json
[
  {
    "id": "cred_abc123",
    "key": "exa",
    "scopeType": "organization",
    "label": null,
    "isDefault": true,
    "createdAt": "2024-11-01T12:00:00Z"
  }
]
```

<ParamField path="--key" type="string">
  Filter the list to instances matching this credential key.
</ParamField>

## `credentials update` — modify an existing credential

Updates the label, default status, or field values of an existing credential instance. You must know the instance ID (from `credentials list`).

```bash
keystroke credentials update <id> [options]
```

```bash
# Update the label
keystroke credentials update cred_abc123 --label "Production API key"

# Rotate the secret value
keystroke credentials update cred_abc123 --set apiKey=sk-newkey...

# Read new value from environment
keystroke credentials update cred_abc123 --set apiKey=@env:EXA_API_KEY

# Mark as default
keystroke credentials update cred_abc123 --default
```

<ParamField path="<id>" type="string" required>
  The credential instance ID (e.g. `cred_abc123`). Retrieve it from `keystroke credentials list`.
</ParamField>

<ParamField path="--label" type="string">
  New human-readable label for the instance.
</ParamField>

<ParamField path="--default" type="flag">
  Mark this instance as the default for its scope.
</ParamField>

<ParamField path="--set" type="string">
  Update one or more field values (`key=value` or `key=@env:VAR`). Repeatable.
</ParamField>

## `credentials delete` — remove a credential

Permanently deletes the credential instance. This cannot be undone.

```bash
keystroke credentials delete <id>

# Example
keystroke credentials delete cred_abc123
```

<ParamField path="<id>" type="string" required>
  The credential instance ID to delete.
</ParamField>

<Warning>
  Deleting a credential that is actively referenced by a deployed agent or action will cause those operations to fail at runtime. Remove or update references before deleting.
</Warning>

## How credentials are used at runtime

When your agent or action code calls a Keystroke integration (for example, the Exa search tool), the framework automatically looks up the matching credential instance from the vault using the integration's key. Your code never sees or handles the raw secret — the framework resolves it transparently at invocation time.

The lookup order is:
1. An explicit instance ID provided in the action call
2. The **default** instance for the project scope (if one exists)
3. The **default** instance for the organization scope

## OAuth-managed credentials

Some integrations — such as Slack, Google Workspace, and GitHub — use OAuth rather than static API keys. For these integrations you **do not** use `keystroke credentials set`. Instead, connect them through the browser OAuth flow in the Keystroke dashboard under **Settings → Integrations**.

<Note>
  OAuth tokens are managed and refreshed automatically by the platform. The `credentials` CLI commands only handle `api_key`-type credentials (static secrets you supply directly).
</Note>

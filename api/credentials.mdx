Credentials are encrypted secrets — API keys, tokens, connection strings — that your agents and actions read at runtime without ever exposing the raw values in source code or environment variables. The credential vault stores each value encrypted and makes it available to actions by key. You can manage credential instances through the HTTP API, or use the `keystroke credentials` CLI commands as a higher-level alternative.

Credential instances are scoped: an instance can belong to your entire organization (`organization` scope), a specific user (`user` scope), or a specific project (`project` scope). The scope determines which agents and runs can access the value.

## POST /credentials/instances — create a credential

Store a new encrypted credential. If an instance for the given `key` already exists in scope, the server returns `409` — pass a `label` to store an additional instance alongside the existing one.

### Request body

<ParamField body="key" type="string" required>
  The credential key, matching the `credentialId` declared in your action definition. For example, `"OPENAI_API_KEY"` or `"STRIPE_SECRET_KEY"`.
</ParamField>

<ParamField body="value" type="object" required>
  The secret value, shaped to match the credential's schema. For simple API keys this is typically `{ "apiKey": "sk-…" }`.
</ParamField>

<ParamField body="scopeType" type="string" required>
  Scope for this credential instance. One of `"organization"`, `"user"`, or `"project"`.
</ParamField>

<ParamField body="scopeId" type="string">
  Required when `scopeType` is `"project"`. Identifies the project this credential belongs to. Omit for `"organization"` scope.
</ParamField>

<ParamField body="label" type="string">
  A human-readable label that distinguishes multiple instances of the same key within the same scope. Required when a second instance already exists in scope.
</ParamField>

<ParamField body="isDefault" type="boolean">
  Whether this instance is the default for its key and scope. Defaults to `true` when it is the first instance in scope.
</ParamField>

### Response

Returns the created credential instance record with status `201`. The secret value is never returned.

<ResponseField name="id" type="string">
  Unique ID for this credential instance. Use it with `PUT` and `DELETE`.
</ResponseField>

<ResponseField name="key" type="string">
  The credential key you provided.
</ResponseField>

<ResponseField name="scopeType" type="string">
  The scope type of this instance.
</ResponseField>

<ResponseField name="scopeId" type="string | null">
  The scope ID, or `null` for organization-scoped instances.
</ResponseField>

<ResponseField name="label" type="string | null">
  The label for this instance, or `null` if no label was set.
</ResponseField>

<ResponseField name="isDefault" type="boolean">
  Whether this is the default instance for the key within its scope.
</ResponseField>

<ResponseField name="authKind" type="string">
  The authentication kind — `"secret"` for manually managed credentials, `"oauth_managed"` for OAuth-connected credentials.
</ResponseField>

### Example

<CodeGroup>
```bash Request
curl -X POST http://localhost:3001/credentials/instances \
  -H 'content-type: application/json' \
  -d '{
    "key": "OPENAI_API_KEY",
    "value": { "apiKey": "sk-proj-..." },
    "scopeType": "organization"
  }'
```

```json Response (201)
{
  "id": "cred_01HZXYZ...",
  "key": "OPENAI_API_KEY",
  "scopeType": "organization",
  "scopeId": null,
  "label": null,
  "isDefault": true,
  "authKind": "secret"
}
```
</CodeGroup>

## GET /credentials/instances — list credential keys

Returns all credential instances visible to the current scope. Secret values are never included in the response — only metadata.

Optionally filter by key using the `key` query parameter.

### Example

<CodeGroup>
```bash Request
curl "http://localhost:3001/credentials/instances"
```

```json Response (200)
{
  "instances": [
    {
      "id": "cred_01HZXYZ...",
      "key": "OPENAI_API_KEY",
      "scopeType": "organization",
      "scopeId": null,
      "label": null,
      "isDefault": true,
      "authKind": "secret"
    },
    {
      "id": "cred_02ABCDE...",
      "key": "STRIPE_SECRET_KEY",
      "scopeType": "organization",
      "scopeId": null,
      "label": null,
      "isDefault": true,
      "authKind": "secret"
    }
  ]
}
```
</CodeGroup>

```bash
# Filter to a specific key
curl "http://localhost:3001/credentials/instances?key=OPENAI_API_KEY"
```

## PUT /credentials/instances/{id} — update a credential

Update an existing credential instance — rotate the secret value, change its label, or toggle whether it is the default.

<ParamField path="id" type="string" required>
  The credential instance ID returned when the instance was created.
</ParamField>

<ParamField body="value" type="object">
  A new secret value to encrypt and store. Omit if you only want to update metadata fields.
</ParamField>

<ParamField body="label" type="string">
  A new label for this instance.
</ParamField>

<ParamField body="isDefault" type="boolean">
  Pass `true` to make this the default instance. Any existing default for the same key and scope is cleared automatically.
</ParamField>

### Example

<CodeGroup>
```bash Request
curl -X PUT http://localhost:3001/credentials/instances/cred_01HZXYZ... \
  -H 'content-type: application/json' \
  -d '{
    "value": { "apiKey": "sk-proj-newkey..." },
    "isDefault": true
  }'
```

```json Response (200)
{
  "id": "cred_01HZXYZ...",
  "key": "OPENAI_API_KEY",
  "scopeType": "organization",
  "scopeId": null,
  "label": null,
  "isDefault": true,
  "authKind": "secret"
}
```
</CodeGroup>

## DELETE /credentials/instances/{id} — remove a credential

Permanently deletes a credential instance and its encrypted secret. This operation cannot be undone.

<ParamField path="id" type="string" required>
  The credential instance ID to delete.
</ParamField>

Returns `204 No Content` on success.

### Example

```bash
curl -X DELETE http://localhost:3001/credentials/instances/cred_01HZXYZ...
```

<Warning>
  You cannot modify or delete OAuth-managed credential instances through the API. Those instances are managed by the OAuth connect flow. The server returns `400` if you attempt to update or delete them.
</Warning>

## Using the CLI instead

The `keystroke credentials` commands cover the most common vault operations without writing curl requests:

```bash
# Set a credential interactively
keystroke credentials set OPENAI_API_KEY

# List all credentials
keystroke credentials list

# Remove a credential
keystroke credentials delete OPENAI_API_KEY
```

<Tip>
  For local development, the CLI is the fastest way to populate your credential vault. The HTTP API is better suited for automated provisioning scripts, CI/CD pipelines, and server-to-server integrations.
</Tip>

Keystroke is a meta-framework for building AI agents, workflows, and triggers in TypeScript — comparable to how Next.js wraps React, Keystroke wraps Hono and a production-ready agent runtime. You write files in `agents/`, `workflows/`, and `triggers/`; the framework discovers them, mounts HTTP routes, and handles execution. Ship your first agent in minutes, then scale to durable multi-step workflows and event-driven triggers without changing how you write code.

## How it works

Every Keystroke project follows the same three steps — from a blank directory to a running agent server.

<Steps>
  <Step title="Scaffold your project">
    Run `keystroke init my-app` to generate a ready-to-run project with a `keystroke.config.ts`, a `src/` directory, and all required dependencies pre-configured.
  </Step>
  <Step title="Define agents, workflows, and triggers">
    Drop TypeScript files into `src/agents/`, `src/workflows/`, and `src/triggers/`. Keystroke discovers them automatically — no manual route registration required. Use `defineAgent`, `defineWorkflow`, and `defineWebhookSource` (or `defineCronSource` / `definePollSource`) to declare your logic.
  </Step>
  <Step title="Run locally or deploy to the platform">
    Start a local dev server with `keystroke dev` (watch mode, port 3001) or `keystroke start` for a stable build. When you're ready to go to production, `keystroke deploy` pushes your project to the Keystroke platform, which manages routing, credentials, and scaling.
  </Step>
</Steps>

## TypeScript SDK

<Note>
  Keystroke ships a typed HTTP client — `@keystrokehq/sdk` — so you can invoke agents and workflows from any TypeScript codebase without hand-writing `fetch` calls. Import it from your frontend, another service, or a test suite. See the [API Reference](/api/overview) for usage.
</Note>
